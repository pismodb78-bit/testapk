# PISMO для Android

Порт Windows-клиента **PISMO** (C#/WinForms) на **Kotlin + Jetpack Compose**.

Приложение работает с **той же базой `bdauth`** и **тем же сервером LiveKit**,
что и десктоп, поэтому пользователи, диалоги, группы, серверы и звонки —
общие между Windows и Android.

> Ориентир для порта — ветка `claude/camera-display-bug-x08ed0` репозитория
> `pismodb78-bit/PISMO_MESSENDGER` (актуальный код на LiveKit).
> В `master` и в теге `2.8.3.4` лежит **старая** версия на WebView2 + coturn —
> с ней звонки Android состыковать нельзя.

---

## Запуск

1. Открыть папку проекта в Android Studio (Ladybug или новее) → **Trust Project**.
2. Дождаться Gradle Sync (скачает AGP 8.7.3, Kotlin 2.0.21, LiveKit, JDBC).
3. Подключить устройство или запустить эмулятор → **Run**.

Минимальная версия Android — **7.0 (API 24)**, целевая — **15 (API 35)**.

### Настройка подключения

Экран настроек (шестерёнка на экране входа) — там же, где на ПК лежат
`ip.txt` и `livekitsettings.json`:

| Параметр | Значение по умолчанию (как на ПК) |
|---|---|
| Сервер / порт | `85.174.248.59` / `3307` |
| База | `bdauth` |
| Пользователь / пароль | `user1` / `scent01` |
| LiveKit URL | `ws://5.181.23.167:7880` |
| WebSocket сигналинга | `ws://<сервер>:8080/` |

Кнопка **«Проверить подключение»** делает `SELECT VERSION()` и показывает
результат — удобно, когда непонятно, сеть это или доступы.

> ⚠️ **Безопасность.** API key и secret LiveKit по умолчанию взяты из
> `PISMO/LiveKitSettings.cs`, который лежит в **публичном** репозитории.
> Эта пара считается скомпрометированной: имея её, кто угодно выпустит токен
> в любую вашу комнату. Ключи следует ротировать на сервере LiveKit и
> вписать новые в настройках приложения (перекомпиляция не нужна).
> Из APK секрет извлекается тривиально (`unzip` + `strings`), поэтому
> зашивать его в код было бы ещё хуже.

## Архитектура

Своего бэкенда у проекта нет — десктоп ходит в MySQL напрямую, и Android
делает так же, через JDBC. Все запросы уходят на `Dispatchers.IO`.

```
core/      Prefs, UserSession, Crypto, PasswordHasher, Jwt, утилиты
data/db/   Db (пул JDBC-соединений), DbMigrator
data/repo/ Auth, Chat, Group, Server, Friends, Reactions, Pins,
           Presence, Call, Profile
data/      MediaCache
media/     WavRecorder/WavPlayer, VideoCircleCodec
call/      CallEngine (LiveKit), LiveKitToken
net/       SignalingClient (WebSocket)
service/   Notifications, PollingService, CallForegroundService
ui/        Compose-экраны и тема
```

### Что обязано совпадать с ПК, иначе не состыкуется

| Механизм | Деталь |
|---|---|
| **Шифрование сообщений** | `enc:v2:` + base64(**nonce(12) ‖ tag(16) ‖ ciphertext**), AES-256-GCM. .NET отдаёт тег отдельно, а `javax.crypto` клеит `ct‖tag` — поэтому при шифровании тег переносится вперёд, при расшифровке возвращается в хвост. Читается и легаси `enc:v1:` (AES-CBC) |
| **Ключ шифрования** | SHA-256 от `PISMO::message::secret::v1::do-not-change` |
| **Пароли** | `pbkdf2$<iter>$<b64 salt>$<b64 hash>`, PBKDF2-HMAC-SHA256, 100 000 итераций. Легаси-plaintext перехешируется при первом входе |
| **Токен LiveKit** | HS256, Base64Url без паддинга. `canUpdateOwnMetadata` **обязателен** — без него сервер молча игнорирует смену атрибутов, и значки мьюта не работают |
| **Имя комнаты** | id call-сессии строкой; для голосового канала — `vch_<id канала>` |
| **identity участника** | id пользователя строкой — по нему ПК сопоставляет плитки |
| **Значки мьюта** | атрибуты `mic` (**`"1"` = микрофон включён**, `"0"` = замьючен) и `deaf` (`"1"` = заглушены наушники). Инверсия на `mic` неочевидна |
| **Голосовые** | WAV 16 кГц / моно / PCM-16 — то, что пишет NAudio. Любой другой контейнер десктоп не проиграет |
| **Видео-кружочки** | контейнер `PSMOVID1`, little-endian |
| **Миграции БД** | те же 14 пунктов и общий журнал `schema_migrations` |

### Отличия от ПК, сделанные намеренно

- **Пул соединений** вместо открытия соединения на каждый запрос: на мобильной
  сети TCP-handshake на каждое действие — это сотни миллисекунд.
- **Время читается через `UNIX_TIMESTAMP()`** прямо в SQL, чтобы JDBC не
  вносил сдвиг часовых поясов (на ПК для этого есть отдельный костыль с
  `TIMESTAMPDIFF(SECOND, UTC_TIMESTAMP(), NOW())`).
- **Фоновый опрос — раз в 10 секунд**, а не 2.5, чтобы не сажать батарею.
  На открытом экране частота та же, что на ПК.

## Что не переносится с Windows

| Windows-механизм | Причина |
|---|---|
| `ProcessLoopbackCapture` — звук конкретного процесса | Android не даёт захватывать звук чужих приложений пофайлово. Системный звук в демонстрации берётся через `AudioPlaybackCapture` (Android 10+), но приложения, запретившие захват, в него не попадут |
| `GameOverlayForm`, `OverlayEditorForm` — оверлей поверх игр | Нет эквивалента |
| `Updater.cs` — самообновление exe | APK обновляется установкой/сторой |
| `GpuPreference`, `NativeNvenc` | Кодирование идёт через `MediaCodec` аппаратно, выбирать нечего |
| `WebRtcTransport`, `WebViewShared` | Мёртвый легаси на WebView2, в рабочем коде ПК не используется |

Заменено эквивалентами, а не потеряно: захват экрана (`MediaProjection`),
шумодав и эхоподавление (WebRTC APM внутри LiveKit), трей и `FlashWindow`
(уведомления Android), скруглённые панели WinForms (Compose).

## Состояние работ

**Готово и пригодно к запуску:**
вход с «запомнить меня», регистрация, смена пароля, список диалогов и групп
с непрочитанными, личная и групповая переписка постранично, отправка текста,
картинок, файлов (с дозаписью кусками по 4 МБ) и голосовых, ответы, правка
с историей, мягкое удаление, реакции, блокировки, кеш медиа, звонки на
LiveKit (микрофон, камера, наушники, демонстрация экрана, плитки участников
со значками мьюта), уведомления, фоновый опрос, настройки.

**Слой данных готов, UI ещё нет:** серверы и каналы, роли и баны, голосовые
каналы с `voice_presence`, друзья и заявки, закреплённые сообщения, профили,
видео-кружочки (кодек готов, экран записи — нет), пересылка, админский режим
«войти за пользователя».

Подробности — в отчёте по задаче.
